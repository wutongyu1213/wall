## `wall` 的 17 个字段

```
id, nickname, target_name, grade_year, class_no, love_tag,
sender_gender, target_gender, love_msg, like_count, dislike_count,
gift, created_ts,
status, author_id, user_key, semantic_review      ← 后 4 个不该对外
```

- `created_ts` 是 **bigint 毫秒时间戳**，不是 timestamptz。时间过滤要传数字。
- `status` 取值含 `ok`（当前 25 条全是 ok）。
- `user_key` 是设备指纹（见 `assets/device-fp.js`），`semantic_review` 是 AI 审核结果。

## `wall_candidates` 的 15 个字段

```
id, kind, nickname, class_no, photo_url, like_count, status, created_ts,
msg, voting_on,
auto_review, reject_reason, reviewed_at, reviewed_by, ai_review   ← 后 5 个不该对外
```

`nickname` 里是**真实姓名**（如「陈楚元」）。配上 `reject_reason`，
任何人都能反推出「谁报名了、谁被拒了、为什么被拒」。

## 已知的 schema 债务

1. **`card_gifts` 有两条指向 `wall` 的外键**
   （`card_gifts_wall_id_fkey` 与 `fk_gifts_wall`），
   导致 PostgREST 的 embed 查询报 `PGRST201` 歧义。清理见 `sql/02`。

2. **没有任何 migrations 目录**。schema 只存在于线上，
   改一次就要重新探一次。建议从今天起所有 DDL 都写进 `sql/`。

## 存储桶 `wall-photos`

- 路径规则：`<kind>/<时间戳>_<设备指纹>_<随机>.jpg`
  → **文件名里带着上传者指纹**，可把同一台设备传的所有照片串起来。
- 匿名可 `createSignedUrl` 任意路径 → 未过审照片也能读（详见 `sql/03`）。
- 匿名可上传（前端直传，暂时必须保留）。

## 权限矩阵（实测）

| 操作 | anon 结果 |
|---|---|
| `select` on `wall` | 200（含内部字段） |
| `select` on `wall_public` | 404（视图未建） |
| `update` / `delete` on `wall` | 401（被 RLS 拦住，✅ 做得对） |
| `rpc/like_wall` | 可调用（幂等，重复赞返回 204） |
| `storage/object/sign/*` | 200（可签名任意路径）⚠️ |
| `functions/v1/wall-photo-sign` | 404（未部署） |
| `functions/v1/wall-fp` | 200（返回 ip_hash） |
| `functions/v1/wall-cache` | 200（**仅返回 13 个白名单字段，无泄漏** ✅） |
