# 自动内容巡检：30 分钟一次，AI 判定，自动隐藏，邮件通知

## 它到底做了什么

```
每 30 分钟（GitHub Actions 定时）
  ├─ 拉取表白墙所有「可见」帖子（最多 60 条）
  ├─ 逐条交给 AI 判定风险 0~1
  ├─ 风险 ≥ 0.75 → 调后台 hide 接口先隐藏（可撤销，不是删除）
  ├─ 顺手扫一遍照片墙文案（只报告，不自动处置）
  └─ 把「隐藏了哪条、为什么」发到你的邮箱
```

跑在 GitHub 的服务器上，**不需要你开电脑**，也不依赖后台页面是否打开。

---

## 你要做的：加 6 个 Secrets（一次性，5 分钟）

打开 `https://github.com/wutongyu1213/wall/settings/secrets/actions`
→ **New repository secret**，逐个添加：

| 名称 | 填什么 | 必填 |
|---|---|---|
| `AI_API_KEY` | agens 给你的 `sk-...` 密钥 | ✅ |
| `AI_BASE_URL` | agens 控制台里的接口地址，形如 `https://xxx/v1` | 建议填 |
| `AI_MODEL` | 模型名，如 `gpt-4o-mini` / `deepseek-chat` | 建议填 |
| `ADMIN_PWD` | 你在表白墙后台使用的管理密码 | ✅ |
| `MAIL_HOST` | 如 `smtp.qq.com` | ✅ |
| `MAIL_PORT` | `465`（SSL）或 `587`（STARTTLS） | ✅ |
| `MAIL_USER` | 你的邮箱账号，如 `xxx@qq.com` | ✅ |
| `MAIL_PASS` | 邮箱**授权码**（不是登录密码） | ✅ |
| `MAIL_TO` | 接收通知的邮箱 | ✅ |

> QQ 邮箱：设置 → 账户 → 开启 SMTP 服务 → 生成「授权码」，把授权码填到 `MAIL_PASS`。
> 163 邮箱同理。**千万别填邮箱登录密码**，会认证失败。

可选（Settings → Variables，非机密）：

| 名称 | 默认 | 说明 |
|---|---|---|
| `RISK_THRESHOLD` | `0.75` | 调高更保守（0.85 只隐藏很明显的）；调低更激进 |
| `MAX_ITEMS` | `60` | 单次最多检查多少条，控制成本 |

> `AI_API_KEY` 填好之前，定时任务会以「跳过」结束（退出码 0，不算失败），
> **不会**每 30 分钟给你发一封失败通知。配好之后下一次定时自动开始工作，无需再动代码。

## 如果第一步就失败

日志里会看到每个候选服务商的返回码，例如：

```
  tideapi.com → 401
  agens.cn:8080(明文) → 401
  DeepSeek → 401
巡检失败：所有候选服务商都没通过认证。
```

**全部 401 = 不是地址问题，是 key 本身无效。** 去网关后台（`https://tideapi.com`）重新生成一个：
很多面板的密钥**只完整显示一次**，关掉就只剩掩码，复制到的是 `sk-xxxx****abcd` 这种残缺串，永远认证不过。
生成后立刻复制、立刻填进 `AI_API_KEY`。

如果是 `404`（而不是 401），那才是地址不对——把 `AI_BASE_URL` 换成后台「令牌/接口」页显示的地址。

> **我已经把 agens.cn 摸清了（2026-11-07 实测），直接照这个填：**
>
> | 地址 | 状态 | 说明 |
> |---|---|---|
> | `https://agens.cn/v1` | ❌ 全 404 | 443 是 nginx 默认页，证书还是自签名（无 subject、10 年有效） |
> | `http://agens.cn:8080/v1` | ⚠️ 真网关，但**明文 HTTP** | 面板标题 `Sub2API - AI API Gateway` |
> | `https://tideapi.com/v1` | ✅ **推荐** | 同一套网关，有正常 HTTPS 证书 |
>
> 判断依据：两个地址对同一个 key 返回**完全相同的错误签名**
> `{"code":"INVALID_API_KEY","message":"Invalid API key"}`，且网关自身配置里
> `balance_low_notify_recharge_url` 指向 `tideapi.com`。
>
> 所以 `AI_BASE_URL` 填 **`https://tideapi.com/v1`**，不要用 `agens.cn`——
> 那个端口是明文，你的密钥和每条学生内容都会裸奔过网。

## 安全：三件必须知道的事

**1. 你刚才在聊天里贴的那把密钥，建议作废重发。**
它已经出现在对话记录里了。去 agens 后台删掉这把、生成新的，再填进 `AI_API_KEY`——**不要填旧的**。

**2. 密钥永远不进仓库。**
本仓库是公开的。工作流通过 `${{ secrets.XXX }}` 注入，日志里不会回显；脚本也不会打印它。
如果有人往代码里硬编码 key，等于公开发布。

**3. 如果 agens 只提供 HTTP，或者 HTTPS 是自签名证书，要谨慎。**
明文 HTTP 意味着你的密钥、以及每条被审的学生内容，都会以明文经过中间网络。
而**自签名证书**意味着客户端无法验证对面到底是谁（中间人可以随便替换）。
`agens.cn:443` 目前出示的正是自签名证书。要用的话至少确认有正规 CA 证书；
没有的话，建议换一家支持标准 HTTPS 的中转（DeepSeek / 阿里百炼 / 硅基流动都在脚本的自动探测列表里，
换过去只需要改 `AI_BASE_URL` 和 `AI_MODEL` 两个值）。

## 已知限制（别踩坑）

| 限制 | 说明 |
|---|---|
| 定时不精确 | GitHub 高峰期可能延迟 3~10 分钟。要秒级准点只能上自己的服务器 |
| 60 天无提交会停 | GitHub 会自动停用长期不活跃仓库的定时任务，届时会发邮件，点一下恢复 |
| 只自动隐藏表白墙 | 照片墙的「隐藏」语义不同（候选表 status），脚本只做报告，由你在后台决定 |
| 隐藏不是删除 | 后台「内容」页可以把误判的帖子恢复可见 |
| 每条都会算钱 | 20 条 ≈ 几分钱。把 `MAX_ITEMS` 设太大没有意义——新内容才需要审 |
